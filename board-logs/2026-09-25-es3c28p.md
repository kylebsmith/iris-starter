# Board log: the starter sketches on an ES3C28P, 2026-09-25

What the sketches did on a real board, in two sessions on the same day: the
first with the sketches' copies of `iris.h` at the library's commit 4cbf12b,
the second (sections 2, 7, 8 and 9) after the copies were synced to the
library's release tag `v0.2.0`. Serial output is copied as the board printed
it. Checks that needed a person at the board say what the person did and
saw.

| | |
|---|---|
| Board | LCDWIKI ES3C28P: an ESP32-S3, revision v0.2, in the 56-pin QFN (quad flat no-lead) package, as esptool reports it |
| Sensor | Adafruit BNO055 on the board's I2C (inter-integrated circuit) socket, SDA (serial data) on GPIO (general-purpose input/output) 16, SCL (serial clock) on GPIO 15; a second device answered there at 0x77, the address `i2c_find` names for BMP/BME pressure sensors |
| Host | macOS 15.6.1 |
| Toolchain | arduino-cli 1.5.1; esp32 board package 3.3.3 (esptool 5.1.0); Adafruit BNO055 1.6.4, Adafruit GFX Library 1.12.5, Adafruit ILI9341 1.6.3 |
| Sketches | first session: iris-starter at commit 98de9c0, every copy of `iris.h` the library's `iris.h` at commit 4cbf12b; second session: iris-starter at commit 9759184, every copy of `iris.h` the library's header as tagged `v0.2.0`, byte for byte |

Two FQBNs (fully qualified board names: the board and its Tools menu
options, as arduino-cli takes them):

- **Documented**, the options in [GET-STARTED.md](../GET-STARTED.md), step 4,
  with USB (Universal Serial Bus) Mode USB-OTG (On-The-Go, driven by TinyUSB):
  `esp32:esp32:esp32s3:USBMode=default,CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB,UploadMode=cdc`
- **Hardware CDC**, the board's default USB Mode, Hardware CDC and JTAG (CDC:
  Communications Device Class, the USB standard for a serial port; JTAG: Joint
  Test Action Group, a debugging interface):
  `esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB`

## 1. `i2c_find`

Built with the documented FQBN. Its serial output from the start of the
capture to the fourth pin pair it tries, SDA 8 / SCL 9, where the capture
stopped (nothing answered on the first two):

```
==================================================================
  I2C SCAN -- looking for your sensor on every plausible pin pair
==================================================================

  FOUND on SDA 16 / SCL 15   -- ES3C28P I2C socket (these sketches' board)
      0x18  = audio codec (on the ES3C28P board itself)
      0x28  = BNO055 orientation (or VL53 distance at 0x29)
      -> in your sketch use:  Wire.begin(16, 15);
      0x38  = FT6336 touch controller (on the ES3C28P board itself)
      0x77  = BMP/BME pressure

  FOUND on SDA 8 / SCL 9   -- ESP32-S3-DevKitC common default
      0x08  = something, but not one I know
```

PASS: the BNO055 answers at 0x28 on SDA 16 / SCL 15, next to the board's own
audio codec (0x18) and touch controller (0x38), and a device at 0x77.

## 3. `iris_instrument`

Built with the documented FQBN and uploaded. The macOS USB device tree shows:

- the device `ESP32S3_DEV`, vendor Espressif Systems (vendor identifier
  0x303a), product identifier 0x1001;
- the interfaces `TinyUSB CDC` (USB class 2, communications) with its data
  interface (class 10), and `TinyUSB MIDI` (class 1, audio).

CoreMIDI, the Mac's MIDI system, lists `ESP32S3_DEV` as both a MIDI source
and a MIDI destination: that is the display name of the endpoints
`MIDIGetSource` and `MIDIGetDestination` return. The sketch's serial port
stays available beside the MIDI device.

PASS: the board appears as a USB MIDI device. On a Mac the device and its
MIDI input and output are all named `ESP32S3_DEV`.

3b. Second session: built again from iris-starter 9759184 with the
documented FQBN and uploaded. A person had Ableton Live listening to
`ESP32S3_DEV`, dragged each bar, then recorded two poses with RECORD at
different bar settings and tilted the board; the screen reported training,
and Ableton showed the incoming MIDI. At the same time a small listener

## 4. Into the loader from a TinyUSB sketch: the 1200-baud tap

`iris_tilt` was uploaded next, built with the Hardware CDC FQBN, over the
TinyUSB sketch then running. A direct `arduino-cli upload` with that FQBN
failed with `Failed to connect to ESP32-S3: No serial data received`, because
it does not restart a TinyUSB sketch. The sketch's serial port was then
opened at 1200 baud and closed with pySerial
(`serial.Serial('/dev/cu.usbmodem441BF6CF88801', 1200)`, then `close()`),
which is what Upload Mode USB-OTG CDC (TinyUSB) makes an upload do (the board
package's `boards.txt` sets `use_1200bps_touch` for that Upload Mode). The
chip came up in download mode on a new port, `/dev/cu.usbmodem1101`, and
`arduino-cli upload --fqbn <Hardware CDC FQBN> -p /dev/cu.usbmodem1101`
uploaded `iris_tilt` there.

PASS.

## 5. `iris_tilt` in Hardware CDC and JTAG mode

In this mode a reset over the serial port reaches the board. Start-up output:

```
iris_tilt

ready. instrument uses 944 bytes

tilt, then press BOOT -- or send any key here except R  ->  demo 1 of 3 (target 0)
```

Three demonstrations were recorded by sending `x` three times over serial,
with the sensor lying still. It trained, then printed this line repeatedly:

```
tilt   0.32  -1.70  ->   64  ################
```

PASS: it starts, records over serial, trains and plays. The three
demonstrations ask for the sketch's three targets, 0, 64 and 127 (`TARGETS`
in `iris_tilt.ino`), with the sensor lying still, and it plays 64, between
them. This checks the path from recording to playing, not the shape of the
mapping.

## 6. `iris_tilt`'s R in Hardware CDC and JTAG mode

Sending `R` restarted the chip, and its ROM (read-only memory) loader printed:

```
ESP-ROM:esp32s3-20210327
Build:Mar 27 2021
rst:0xc (RTC_SW_CPU_RST),boot:0x2 (DOWNLOAD(USB/UART0))
Saved PC:0x40378cba
waiting for download
```

Then `esptool --port /dev/cu.usbmodem1101 --before no-reset --after no-reset chip-id`
connected without touching a button. Its output included
`Connected to ESP32-S3`, the chip type `ESP32-S3 (QFN56) (revision v0.2)` and
`Stub flasher running.` (excerpts, not the whole output).

PASS: **R** enters download mode in Hardware CDC and JTAG mode with no button.

## 8. `boilerplate/stemma_bno055`

Second session: built with the documented FQBN and uploaded, with no knobs
attached, so the targets are whatever the unconnected knob pins read; the
test is whether the instrument survives, not what it plays. Before any tap the
capture held nothing from it: its start-up lines were printed before the port
was read, as in section 2. Its first line in the capture is
`demonstrations: 1`, so it held no demonstrations before the first tap and no
saved instrument had been loaded. The person tapped SAVE
(the BOOT button) at several poses, held the board still, held SAVE until it
saved, unplugged the board and plugged it back in without touching SAVE. The
status lines before the unplug, as printed:

```

demonstrations: 2
trained.
learning -- keep moving it, it stays alive.
demonstrations: 3
trained.
learning -- keep moving it, it stays alive.
demonstrations: 4
trained.
learning -- keep moving it, it stays alive.
demonstrations: 5
learning -- keep moving it, it stays alive.
demonstrations: 6
trained.
kept. 536 bytes in flash, 6 demonstrations, trained.
```

The last three complete lines it played before the unplug (the next was cut
off by it):

```
0.175 0.037 0.064
0.175 0.037 0.064
0.175 0.037 0.064
```

After the replug, with no tap:

```
loaded the instrument from last time.
ready. tilt the board, set the knobs, tap SAVE to record.
hold SAVE for a second to keep the instrument through a power cycle.
```

and it went on playing, 971 lines while the port was read: four lines of
`0.183 0.037 0.067`, then 967 of `0.173 0.037 0.062`.

PASS: the instrument was kept in flash and loaded on power-up, and it played
at once. The numbers differ slightly from those before the unplug. The loaded
network is the one that was saved, so the difference is in what the sensor
read after the board was unplugged and plugged back in.
